# 升级到 1.9

## 升级本机

1. 退出游戏，从托盘完全退出存档管理器。
2. 备份原配置和存档目录。旧版通常为 `GameSaveManager.config.json` 和 `save_data`，自定义位置请一并备份。
3. 安装新版，保留应用数据。
4. 启动后检查游戏列表、存档位置和历史记录。

旧配置会自动转换，新版可读取已有的 ZIP 存档。

旧设置中的游戏安装位置能唯一对应游戏时，会自动成为该游戏在对应设备上的安装目录。需要选择的位置保留在 **设置 → 自动扫描 → 待确认的旧安装位置**。确认后，也可以在游戏的 **查看受管理文件** 中修改。

## 升级本地旧备份

在 **设置 → 备份设置 → 升级旧备份** 中查看备份数量和预计额外空间，再点击 **开始升级**。

- 升级后使用“时间 + 随机后缀”的文件名，解压即可查看存档和恢复说明。历史记录、备注、先后关系和当前存档标记保留。
- 暂停或离开页面会在当前备份处理完后停止；重新打开可继续。升级只读取备份文件，不改动游戏当前存档。
- 缺失、损坏或无法对应存档条目的备份会列为待处理，不妨碍其他备份升级。按提示选择同一备份的完好副本，或确认对应条目后重试。
- 原件保留在备份目录的 `.rgsm-upgrade/originals` 中。确认新版备份可用后，点击 **清理原件**；手动选择的副本不会被删除。

这个入口只升级本地已有文件，不下载或替换旧云端副本。已有 1.9 云库内部格式升级另行处理。

## 升级云端资料库

1. 备份云端数据，让参与同步的设备都升级到兼容的 1.9 版本。
2. 打开 **同步**，按提示选择 **升级到新资料库**。
3. 完成后，在其他设备连接同一个云端位置。

旧版云端内容会保留。后续同步使用新版资料库。

升级中断时，使用继续升级入口。资料库不完整时，保留现状并[提交日志](../issues.mdx)。

## 回退

另存升级后新增的进度，再使用升级前的完整备份和对应旧版程序恢复。
