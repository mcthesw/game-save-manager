# 云同步

云同步可以帮你在多台设备之间接续游戏进度，并为存档在云端保留一份备份。本软件支持 **WebDAV** 和 **Amazon S3**（以及 MinIO、Cloudflare R2 等兼容 S3 的对象存储）两种云端后端。

云同步按**每个游戏、每台设备**单独开关，并记住你为它选择的同步模式。关闭某个游戏的云同步后不进行任何云端读写，本地的备份、恢复、自动备份和额外备份都照常工作；重新开启时，会把这段时间累积的存档记录补发到云端（不会自动补传存档文件），然后按记住的模式继续。

## 选择适合你的同步模式

| 模式 | 说明 | 适合谁 |
| --- | --- | --- |
| **手动** | 自动同步存档记录，文件传输全由你控制 | 偶尔上传存档，或想完全掌控每一次传输的时机 |
| **云备份** | 新存档自动上传到云端 | 主要在一台设备上玩，希望云端总有最新备份 |
| **多设备同步** | 自动下载所需进度，覆盖前先备份 | 在电脑、掌机等多台设备之间接力同一款游戏 |

三种模式的准确含义：

- **手动**：自动把存档记录和当前进度同步到云端，其他设备能看到你玩到了哪里；但上传、下载存档文件，以及把存档应用（覆盖）到游戏，始终由你手动进行。
- **云备份**：在手动的基础上，新增**自动上传**——本设备每产生一个新存档，就自动上传到云端。下载存档、应用存档仍需手动。
- **多设备同步**：在云备份的基础上，新增**自动接续**——当另一台设备沿着同一条进度线走在你前面时，本设备只下载继续游戏所需要的那一个存档并自动应用；覆盖游戏存档前会自动备份当前进度，随时可以回退。

:::note 任何模式都不会自动下载全部历史存档
无论选择哪种模式，软件都不会把所有历史存档自动搬到每台设备上。“下载单个存档”和“下载全部存档”永远是你手动触发的操作，同步模式只决定“继续游戏所需的那一个存档”是否自动送到位。
:::

:::warning 额外备份不参与云同步
额外备份只保存在本设备上，不受云同步管理。
:::

### 自动行为对比

| 行为 | 手动 | 云备份 | 多设备同步 |
| --- | --- | --- | --- |
| 同步存档记录与当前进度 | 自动 | 自动 | 自动 |
| 新产生的存档上传到云端 | 手动 | 自动 | 自动 |
| 下载继续游戏所需的进度 | 手动 | 手动 | 自动，且只下载所需的那一个存档 |
| 下载单个 / 全部历史存档 | 手动 | 手动 | 手动 |
| 把存档应用（覆盖）到游戏 | 手动 | 手动 | 自动，且应用前自动备份当前进度 |

如果断网或暂时关闭了云同步，恢复联网或重新开启后，软件会自动把累积的存档记录补发到云端，但不会自动补传存档文件——需要时到存档管理页面手动上传即可。

## 配置云端存储

在存档管理器的“同步”设置中选择后端并填写账号信息，测试成功后保存。保存后**不需要**手动做全量上传：到各游戏的同步概览中开启云同步、选好模式即可，之后的备份会按所选模式自动处理。

### WebDAV

> 注意，坚果云会限制短时间内的访问次数。当你的游戏数量较多时，建议使用 S3 进行云同步，或换用其他 WebDAV 服务。

以坚果云为例。首先登录你的账户：

![坚果云1](/img/cloud/step1_jianguoyun.jpg)

点击右上角你的用户名，选择“账户信息”，在下一个页面点击“安全选项”，然后添加应用：

![坚果云2](/img/cloud/step2_jianguoyun.jpg)

填写应用名称并确定后，你就获得了同步所需的服务器地址、账号和应用密码。接下来打开存档管理器，进入“同步”设置，选择 WebDAV 后端并输入对应信息：

![存档管理器1](/img/cloud/step3_manager.jpg)

填写完毕后进行测试，测试成功即可保存：

![存档管理器2](/img/cloud/step4_manager.jpg)

使用其他 WebDAV 服务同理：准备服务器地址、账号和密码（或应用密码）即可。

### S3

如果你使用 Amazon S3 或兼容的对象存储服务（如 MinIO、Cloudflare R2），请在同步设置中选择 S3 后端，并填写以下信息：

- **Endpoint**：服务端点 URL（如 `https://s3.amazonaws.com`）
- **Bucket**：存储桶名称
- **Region**：区域（如 `us-east-1`）
- **Access Key ID**：访问密钥 ID
- **Secret Access Key**：访问密钥

填写完毕后进行测试，测试成功即可保存。

> 注意：请确保你的存储桶已创建，且访问密钥具有读写权限。

:::tip 高级设置
云同步的并发数量等高级选项可通过配置文件调整，参见[配置文件说明](./json.md)。
:::

## 同步状态与存档分布

每个游戏的“同步概览”汇总各设备的进度和存档分布数量；存档历史列表与具体操作（备份、应用、单个上传或下载、移除副本）仍在“存档管理”页面进行。

看到进度不等于能恢复进度：进度记录和存档文件是分开的，若那一步的存档文件还没有上传到云端，其他设备看得到进度也暂时无法恢复。

每个存档按“本设备 × 云端”有没有文件分为四种状态：

| 本设备 | 云端 | 含义 |
| --- | --- | --- |
| 有 | 有 | 本设备和云端各有一份 |
| 有 | 无 | 只在本设备：尚未上传，或只保留在本地 |
| 无 | 有 | 在云端：需要时下载即可 |
| 无 | 无 | 另一台设备最后报告持有它，需由持有它的设备上传；若所有设备与云端都没有已知副本，这条进度暂时无法恢复 |

## 进度分叉与冲突

**同一条进度线上的你追我赶不是冲突。** 如果另一台设备是沿着你的进度继续往前玩的，这属于正常前进：多设备同步会自动下载并应用所需的存档；其他模式会提示你有可接续的进度，由你决定是否应用。存档还没上传、记录稍微滞后，也都不算冲突。

**真正的分叉**是指两台设备从同一个点各自玩出了不同的进度线（例如断网期间两台设备都在玩）。这时多设备同步会**暂停自动同步**（你的模式设置保持不变），并请你在三者中选一个：

1. 保留本设备的进度，把它发布给其他设备（不强制上传存档文件）；
2. 接受另一台设备的进度（需要其存档文件可用，应用时仍会先自动备份本设备当前进度）；
3. 暂不决定，稍后再处理。

分叉解决后，多设备同步会自动恢复。

## 删除存档与释放空间

:::warning
删除与覆盖类操作不可撤销，执行前请仔细阅读软件弹出的后果提示。
:::

“删除”有三种完全不同的含义：

| 操作 | 影响范围 | 后果 |
| --- | --- | --- |
| 移除本机副本 | 仅本设备上的存档文件 | 存档记录保留。云端或其他设备还有副本时，之后可重新下载 |
| 从云端移除 | 仅云端上的存档文件 | 存档记录保留。本设备或其他设备还有副本时，之后可重新上传 |
| 从所有设备和云端永久删除 | 所有设备与云端的全部副本 | 不可恢复。本设备与云端的副本随即移除；处于离线的设备会在下次联网时得知这条删除记录，并移除自己手上的副本，被删除的存档不会再“复活” |

- 移除本机或云端副本前，软件会说明移除后的影响；如果移除之后将没有任何已知副本，会给出更强烈的警告。移除副本不会影响存档记录，历史列表里仍能看到这条进度（只是暂时没有可用的文件）。
- 永久删除一条存档时，如果发起设备当前的进度正好在这条存档上，需要先做一个选择：受保护地应用另一条存档、把当前游戏进度存为一条新存档，或清除当前进度（保留游戏里的存档文件）。
- 其他设备不会阻止永久删除。它们联网得知删除后，指向这条存档的进度会被清除，之后需要重新选择一条已有进度，或把当前游戏存为新进度——软件不会自动把设备退回更早的进度。
- “关闭云同步”只是可逆的设置，不等于删除任何数据；整个游戏的永久删除入口只位于同步概览。
