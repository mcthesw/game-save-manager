# 云端同步端到端测试

`pnpm web:e2e`

## 升级中断后恢复

升级开始、迁完第一份存档后被打断，云端旧数据应原样保留。

- 重启后能接着完成升级
- 再重启不产生重复存档
- 旧的上传方式被拒绝

## 两台设备先后升级再协作

1. 两台都还在旧云端。A 把存档上传到云，B 从云下载到同一份
2. A 先升级，B 仍是旧云端，B 被提示加入
3. B 保留云端数据加入，两台都上了新云端，旧上传方式被禁用
4. A 把新存档上传到云，B 从云拉取并应用那一份
5. A 改自己的同步模式，云上 B 的模式不变
6. 两台从云上同一份存档各自分叉并各自上传，A 必须明确选择云上 B 那条
7. A 删除当前存档后回退到上一份；云上该条被标记删除，B 不得再把它拉回来
8. 两台都重启后，各自与云上的状态仍一致

## 两台设备互不干扰

- 两台设备 ID 不同
- 各自的本机数据和登录凭证不交叉
- A 的页面只打到 A，B 的页面只打到 B
- 用 B 的凭证打不开 A
